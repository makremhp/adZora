# adZora

منصة إعلانات عربية مستقلة قيد التطوير، تربط بين المعلنين والناشرين مع واجهة عربية RTL وتجربة Mobile First.

## الحالة الحالية

- ✅ صفحة تسويقية عربية متجاوبة.
- ✅ توحيد الهوية الظاهرة إلى adZora.
- ✅ استخدام خط Tajawal للواجهة العربية.
- ✅ قائمة Navbar متجاوبة للهاتف مع الإغلاق عند اختيار رابط أو الضغط خارجها أو استخدام Escape.
- ✅ تحسين لوحة المعلن على الهاتف: الإحصائيات وجدول الحملات يتكيفان مع العرض الصغير.
- ⚠️ تسجيل الدخول الحالي تجريبي ولا يوجد Backend أو قاعدة بيانات بعد.
- ⚠️ أرقام الحملات والإحصائيات الحالية بيانات عرض وليست مصدرًا حقيقيًا.

## آخر ما تم إنجازه

### تحسين لوحة المعلن للهاتف

- منع لوحة التحكم من التسبب في تمرير أفقي على الهاتف.
- تحويل جدول الحملات إلى صفوف شبيهة بالبطاقات عند عرض الهاتف.
- إضافة تسميات واضحة لكل قيمة داخل صف الحملة.
- ترتيب رأس اللوحة وبطاقة الحساب والإحصائيات بشكل مناسب للشاشات الصغيرة.
- جعل زر إضافة حملة بعرض كامل على الهاتف.

## ما لم يتم بناؤه بعد

- نظام حسابات حقيقي وصلاحيات admin وadvertiser وpublisher.
- Backend وREST API وقاعدة PostgreSQL.
- إنشاء الحملات وإدارتها فعليًا.
- Publisher Panel وAd Zones.
- Ad Server وTracking.
- Ledger والمدفوعات وطلبات السحب.
- لوحة الإدارة ومراجعة الحملات والمواقع.
- Analytics حقيقية ومكافحة الاحتيال.

## الخطة المرحلية التالية

1. تقسيم واجهة لوحة المعلن إلى أقسام واضحة مع الحفاظ على Mobile First.
2. بناء نموذج إنشاء حملة متجاوب كخطوة واجهة فقط.
3. إضافة Backend وقاعدة البيانات بعد تثبيت تجربة الواجهة.
4. ربط المصادقة والصلاحيات بالبيانات الحقيقية.
5. بناء Publisher Panel ثم Ad Server وTracking.

## ملاحظات مهمة

هذا المشروع يطوّر على مراحل صغيرة. كل تعديل يجب أن يحافظ على الهاتف والكمبيوتر، وأي أرقام مالية أو إحصائيات حقيقية يجب أن تأتي لاحقًا من الخادم وليس من localStorage أو بيانات ثابتة في الواجهة.


### نموذج إنشاء الحملة — واجهة أولية

- ✅ إضافة نافذة إنشاء حملة داخل لوحة المعلن.
- ✅ الحقول الأساسية: الاسم، نوع التسعير، نوع الإعلان، الميزانيات، سعر العرض، الاستهداف، والأوقات.
- ✅ تصميم متجاوب للهاتف والكمبيوتر مع نافذة قابلة للتمرير عند الحاجة.
- ✅ إضافة رسالة واضحة بأن النموذج تجريبي ولا يحفظ بيانات حقيقية بعد.
- ⏳ الخطوة التالية: ربط النموذج بالـAPI والتحقق Server-Side وحفظه كمسودة في قاعدة البيانات.


### Publisher Panel والـNavbar

- ✅ إضافة صفحة ناشر أولية داخل لوحة التحكم من خلال زر المواقع والمساحات.
- ✅ إضافة قسم مواقعي مع حالة الموقع، Ad Zones، Impressions، Clicks، وRevenue.
- ✅ إضافة عرض حدود الترافيك وTrust Tier كواجهة تمهيدية.
- ✅ إضافة نافذة إضافة موقع مع الحقول الأساسية والتحقق المبدئي من HTTP وHTTPS.
- ✅ جعل أزرار لوحة التحكم تغيّر الأقسام أو تعرض حالة واضحة بدل أن تكون بلا استجابة.
- ⚠️ بيانات الناشر الحالية للعرض فقط، ولم يتم حفظ المواقع أو إنشاء Verification Token بعد.
- ⏳ الخطوة التالية: ربط إضافة الموقع والتحقق منه بالـAPI وقاعدة البيانات.

- ✅ إضافة تنقل داخلي للموبايل للوصول إلى أقسام لوحة المعلن والناشر.

## سجل التحديثات — فصل تجربة الناشر والمعلن

### 15 سبتمبر 2026 — Role-based Frontend

- فصل صفحات وتجربة **المعلن** عن **الناشر** داخل الواجهة حسب الدور المختار عند التسجيل أو تسجيل الدخول التجريبي.
- إضافة اختيار واضح في Landing Page تحت عنوان **Are you?** بزرين مستقلين: ناشر لإدارة المواقع وتحقيق الدخل، ومعلن لإطلاق الحملات.
- إضافة Navbar علوي ثابت داخل الحساب للتحكم في الانتقال بين الصفحات، مع إبقاء Sidebar متجاوبًا للشاشات الكبيرة وقائمة Select للهاتف.
- إظهار الرصيد التجريبي **$0.00** في أعلى الصفحة لكل من الناشر والمعلن.
- إضافة محفظة جانبية احترافية مع إيداع تجريبي، بالإضافة إلى صفحة محفظة كاملة داخل الحساب.
- إضافة صفحات الإحصائيات والإعدادات للمعلنين والناشرين مع محتوى يتغير حسب الدور.
- إضافة صفحة الناشر التي تشمل المواقع، Ad Zones، الظهور، النقرات، والأرباح.
- إضافة نافذة إنشاء Ad Zone تجريبية مع الاسم، النوع، المقاس، والموقع المرتبط.
- الحفاظ على RTL، الوضع الليلي، والتجاوب مع الهاتف، مع تحسين التنقل بعد تسجيل الدخول.

## سجل الأخطاء والحدود المعروفة

- [Backend] التسجيل وتسجيل الدخول تجريبيان؛ لا توجد جلسات أو صلاحيات حقيقية بعد.
- [Payments] الرصيد والإيداع يعتمدان على localStorage للمعاينة فقط، ولا يتم تحصيل أي أموال.
- [Data] الإحصائيات، المواقع، وAd Zones بيانات عرض ولا تمثل مصدرًا حقيقيًا قبل بناء API وقاعدة البيانات.
- [Validation] التحقق الحالي من الروابط والنماذج يتم في المتصفح فقط ويجب تكراره Server-Side.
- [Mobile] تمت معالجة القوائم والبطاقات للشاشات الصغيرة، لكن اختبار أجهزة فعلية يبقى مطلوبًا قبل الإطلاق.
- [Security] لا يجب اعتبار التخزين المحلي Ledger أو نظام صلاحيات أو مصدرًا موثوقًا للرصيد.
